## 5. Data health

Coverage is stable (eligible pool about 3,000; IFRS cohort steady at 93). All
12 nightly runs green. But the review found four integrity problems.

**SPY benchmark missing on 20 of 42 snapshot days (fixed).** The portfolio
step fetched SPY with a separate single-ticker call made right after the
scan's ~20 bulk price batches. On the cloud runner that call was throttled
and, unlike the stock batches, never retried, so the "vs SPY" curves were
half holes. SPY now rides inside the scan's own batched, retried download and
is stored on the scan record, so the benchmark is priced from the same pull
as every stock mark. The 20 missing values were backfilled from SPY's daily
history, each anchored to the close its scan's stock prices came from.
Boundary check: no artificial jump between recorded and backfilled points
(−0.08% across the seam). The series is price-only, the same basis as the
books.

**Scan labels a day late on 21 of 43 scans (fixed).** Scans were labelled
with the runner's calendar date. GitHub fires the 21:30 UTC job late, and all
10 recent runs started after midnight UTC, so each carried the next day's
label. This was a live data-loss risk: one on-time run would reuse the
previous night's label, and same-date replacement would delete that scan.
Scans are now labelled with the trading date of their prices. A committed,
idempotent migration (`scripts/2026-11_relabel_scans_by_price_date.py`)
relabelled history, keeping every original label in `scans.run_label`.

It exposed one duplicate: the 2026-10-16 close had been scanned twice (the
nightly run, then the IFRS re-run next morning), stored under two labels and
silently double-counting that day. The later scan, the one the books were
marked against, is canonical. The earlier was **moved** to `scans_superseded`
and `scores_superseded` with its reason, not deleted. All 24 evaluations and
82,710 outcome rows are intact.

**`--sample` runs could overwrite the day's full scan (fixed).** The
no-degrade guard skipped sample runs. A sample run now refuses to replace a
full scan.

## 6. Proposed changes (not shipped)

Both rewrite recorded numbers, so they need an explicit decision.

### A. Total-return accounting

**Evidence.** Forward returns and the books are price-only.

| | measured |
|---|---|
| anchor top decile, price only | +0.08% |
| anchor top decile, with dividends | **+0.46%** |
| top-decile names paying a dividend in the window | 44 of 320 |
| dividends on current holdings never credited: aggressive | $654.85 (0.65%) |
| core | $36.64 |
| monkey | $29.74 |

The bias is not neutral. It systematically understates high-yield stocks,
which the value and low-vol factors favour, so it depresses the measured
value IC and handicaps the dividend-heavy books in the A/B comparison.

**Proposal.** Fetch bulk prices with `actions=True`, which returns dividends
and splits for every symbol in the same request (no extra calls). Then
(1) measure forward returns from the current dividend-adjusted series, which
is total return by construction; (2) credit book cash with each holding's
dividends on its ex-date as a `DIV` ledger entry, including those already
missed. Move the benchmark to SPY total return at the same time so the
comparison stays like-for-like.

**How we will know it worked.** ARI's anchor outcome reads about +3%, not
−63%, and no book's cash diverges from its holdings' dividend history.

### B. Split-adjusted share issuance

**Evidence.** 232 stocks show a share count change above 50% in a year; in a
20-stock sample, 4 were stock splits rather than dilution or buybacks.
Issuance compares raw share counts, so a 2:1 split reads as 100% dilution and
a reverse split as a huge buyback. About 45 eligible stocks are likely
affected, each with its value score moved by roughly ±0.85.

**Proposal.** Split-adjust the prior share count with the split history from
proposal A's download. **How we will know:** the >50% tail shrinks and no
remaining member of it has a split in the window.
